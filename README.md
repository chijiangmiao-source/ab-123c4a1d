# 束线联锁规程 · ioco 静止输出复核

升级束线联锁控制器前，在网页分别录入**旧规程（规范）**与**候选规程（实现）**
的有限位置、初始位置、输入命令与带输入/输出标签的迁移，输出可明确标记为
「静止」，提交后读取 ioco 复核结论。

## 判定语义

按经典 **ioco（Tretmans）** 判定，纳入内部静默与可观察静止：

- `静默` 为内部 τ 迁移；判定在状态集上做 **τ 闭包**（`after` 始终闭包）。
- `静止` 为可观察输出 δ：显式标记的静止位置可观察 δ；没有任何输出且不能
  经 τ 到达输出的停滞位置同样可观察 δ；δ 在静止位置上为自环。
- 对每条双方可执行的**暂停轨迹** σ（由输入、输出、δ 组成），要求
  `out(候选 after σ) ⊆ out(旧规程 after σ)`。
- 反例为 BFS 得到的**长度最短**暂停轨迹，同一深度按标签 **ASCII 顺序**
  展开，故反例历史确定、可复现；状态集对做访问剪枝，带环迁移也必然终止，
  **不做状态名对应、不做有限长度枚举、不做随机回放**。

返回证据包含：最短历史、两侧**逐步闭包状态集**、候选可能输出、旧规程允许
输出，以及候选多出的未允许输出。

## 标签语法

| 录入 | 含义 |
| --- | --- |
| `命令?` | 可观察输入 |
| `报警!` | 可观察输出 |
| `静默` | 内部 τ 迁移（目标填下一位置） |
| `静止` | 将源位置的输出明确标记为静止 δ（目标位置填本位置） |

## 本地运行（无需第三方依赖，Python 3.11+）

```bash
python -m app.server                 # 默认 0.0.0.0:8080
IOCO_PORT=9090 python -m app.server  # 可配置端口
```

打开 `http://localhost:8080/`，页面内置三个示例：仅位置改名（一致）、
命令后报警（不一致）、静默后未允许确认（不一致）。

## 接口

```
POST /api/verify
{
  "spec":      {"name":"旧规程","locations":"S0,S1","initial":"S0",
                "transitions":[{"from":"S0","action":"命令?","to":"S1"}, ...]},
  "candidate": { ...同结构... }
}
```

- `200 {"verdict":"consistent|inconsistent", ...证据...}`
- `400 {"ok":false,"errors":[{"side":"spec|candidate","message":"..."}]}`

非法标签、悬空迁移、缺少初始位置/有限位置、同一标签下重复状态声明都会
**定位反馈**（指明规程侧与迁移序号）；校验失败时响应不含结论，页面同时
清除先前结论。结论完全由当次请求计算，服务端不保存任何状态。

健康检查：`GET /healthz`。

## 测试

```bash
python -m unittest discover -s tests -v   # 25 个用例：语义 + 真实 HTTP
```

## Docker / Compose

```bash
docker compose up --build web       # 开放端口可用环境变量配置：
IOCO_HOST_PORT=9090 docker compose up --build web

docker compose up --build verify    # 一次性核对服务
docker compose ps -a                # 查看 verify 退出码
```

`verify` 服务等待 `web` 健康检查通过后，顺序执行并**报告退出码**
（0 通过，非 0 失败），完成即退出（`restart: "no"`）：

1. **代码测试**：`unittest` 全量；
2. **构建检查**：`compileall` 字节码编译；
3. **HTTP 冒烟**：经真实接口提交「候选 `命令? → 静默τ → 报警!`，
   旧规程命令后只能静止」，核对结论 `inconsistent`、最短历史 `[命令?]`、
   未允许输出 `[报警!]`、旧规程允许输出 `[静止]`、末步候选闭包
   `[C1, C2]`（证明纳入静默 τ）；并附带「仅位置改名 ⇒ 一致」控制用例。
